# Social AI: Safety and Storage Optimizations

This note records the improvements made after comparing the project with the
course baseline. The original lesson flow is still recognizable, but the
project now avoids a few practices that are acceptable in a classroom demo and
unsafe in a real deployment.

## 1. OpenAI Key Is No Longer Sent to the Browser

The course version used `REACT_APP_OPENAI_KEY` and initialized the OpenAI client
inside `Landing.js`. React variables beginning with `REACT_APP_` are compiled
into the browser bundle, so that key could be exposed to anyone who opens the
site.

The updated flow is:

```text
React Landing page
  -> POST /generate-image with a prompt and JWT
  -> Go handler/image.go
  -> OpenAI Images API
  -> imageDataUrl returned to React
  -> optional POST /upload to save it as a Social AI post
```

Set the key only in the PowerShell window that starts the Go backend:

```powershell
$env:OPENAI_API_KEY = "your-key"
$env:OPENAI_IMAGE_MODEL = "gpt-image-2"
go run .
```

Do not put the key in `social-ai/.env`. When the key is absent, only the AI
image button is unavailable; login, upload, search, deletion, and the media
collection still work.

## 2. Uploads Have a Size Limit

`handler/post.go` now limits each image or video upload to 20 MB. This protects
the local `uploads` directory and avoids accidentally consuming a large amount
of disk space during testing.

Deleting a post now deletes the associated local file or Google Cloud Storage
object as well. The original course flow removed only the Elasticsearch record,
which would eventually leave unused media files behind.

## 3. Browser Origins Are Explicit

The backend previously allowed every website to call its APIs. Local
development now defaults to only:

```text
http://localhost:3000
```

For a deployed frontend, configure the allowed addresses before starting Go:

```powershell
$env:SOCIALAI_ALLOWED_ORIGINS = "https://your-frontend.example.com,http://localhost:3000"
go run .
```

## 4. Private Files Stay Out of Git

The new root `.gitignore` prevents these local-only files from being committed:

- `socialai/conf/deploy.yml`
- `socialai/uploads/`
- `social-ai/.env`
- React `node_modules` and `build`

Use `socialai/conf/deploy.local.example.yml` as the local configuration
template. Copy it to `deploy.yml`, set a long random token secret, and keep the
copy on your own machine.
