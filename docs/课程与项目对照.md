# Social AI 课程与项目对照

## 课件对应的功能

| 课件内容 | 项目文件 | 做成的结果 |
| --- | --- | --- |
| Social AI Web 1 路由 | `social-ai/src/components/Main.js` | `/login`、`/register`、`/create`、`/collection` 四个路由和登录拦截 |
| Go upload API | `socialai/handler/post.go` | `POST /upload` 接收图片或视频表单 |
| Elasticsearch | `socialai/backend/elasticsearch.go` | 自动创建 `user`、`post` 两个索引，支持保存、搜索和删除 |
| GCS | `socialai/backend/storage.go` | 云端使用 GCS；本地开发使用 `uploads` 文件夹 |
| JWT Authentication | `socialai/handler/auth.go`、`user.go` | 注册、登录、签发 token，并保护上传、搜索、删除接口 |
| GAE + CORS | `socialai/app.yaml`、`handler/router.go` | GAE 配置和浏览器跨域请求支持 |
| Web 2 Header | `ResponsiveAppBar.js` | 固定导航栏、Create、Collection、Log out |
| Web 3 Account | `Login.js`、`Register.js` | Ant Design 表单调用 `/signin`、`/signup` |
| Web 4-6 Collection | `SearchBar.js`、`PhotoGallery.js`、`CreatePostButton.js` | 搜索、相册预览、图片删除、图片视频上传 |
| Web 7 AI image | `Landing.js` | 使用 OpenAI `gpt-image-2` 生成图片，并上传到 Social AI Collection |
| Amplify | `social-ai/build` | `npm run build` 已成功生成，可按课件上传到 AWS Amplify |

## 本地运行顺序

1. 在 `Z:\Program\java\Social` 执行 `docker compose up -d`，启动 Elasticsearch。
2. 在 `socialai` 目录执行 `go run .`，启动后端。
3. 在 `social-ai` 目录执行 `npm.cmd start`，启动前端。
4. 打开前端页面，先注册，再登录，然后进入 Collection 上传媒体。

## 与课件的两个必要修正

1. 课件的 Elasticsearch Go SDK 写法使用 `ID`，当前 `olivere/elastic/v7` 的实际方法名是 `Id`，否则无法编译。
2. 课件的用户名校验正则只会匹配一个字符。项目改为 3-30 位字母、数字或下划线，避免合法用户名被错误拒绝。

JWT、索引结构、接口路径、GCS、GAE 和 React 页面分工均按课件的设计保留。
